# 天河体育中心周边地图可视化导航系统

在浏览器里运行的**地图可视化导航系统**：上传一张自己的地图图片，在上面标注节点、
连成双向道路、校准比例尺，然后查询两点之间的全部简单路径与最短路径。

- 底图**必须由你上传**，系统运行中不联网获取地图，也不会自动替换底图
- 所有坐标以**原始图片像素**为唯一基准，缩放/拖动/导出都不会改变数据
- 纯前端、无后端，构建产物是静态文件，可直接部署

> 仓库自带的 `test-map.png` 是 1600×1200 的示意底图（带像素网格），
> **仅用于自动化测试与功能演示**，请勿当作真实地图使用。

## 快速开始

### 环境要求

| 项目 | 要求 |
| --- | --- |
| Node.js | ≥ 20（实测 v24.16.0） |
| 包管理器 | pnpm（实测 11.21.0）；也可用 npm |
| 浏览器 | Chromium 内核（Chrome / Edge），已实测 |

### 安装与启动

```bash
pnpm install
pnpm dev          # 打开终端输出的地址，默认 http://127.0.0.1:5173/
```

### 生产构建与预览

```bash
pnpm build        # 类型检查 + 打包，产物在 dist/
pnpm preview      # 本地预览生产构建，默认 http://127.0.0.1:4173/
```

| 层 | 选型 |

## 功能一览

| 模块 | 能力 |
| --- | --- |
| 底图 | 上传 / 更换 / 移除；显示原始尺寸；自动适配窗口；滚轮缩放、拖动平移、1:1 原始像素 |
| 节点 | 点击地图添加、按原始像素坐标手动添加、选中、改名、改坐标、改类型、删除、边界校验 |
| 道路 | 两个已有节点作端点、任意多个中间点、完成/取消/重新绘制/删除、拖动中间点改线、双向 |
| 比例尺 | 地图点选两点 + 输入已知距离与单位；米/像素换算；未校准只显示像素 |
| 路径搜索 | 全部简单路径（DFS 穷举）+ 最短路径（Dijkstra）；结果数量保护与完整性标注 |
| 路线可视化 | 起点/终点/路线节点配色区分、按真实折线高亮、多路线切换、无路径清除旧高亮 |
| 项目管理 | 导出 `.tianhe.json`（内嵌底图）、导入前完整校验、覆盖前确认可取消、非法文件清晰报错 |

或从下拉框中选择。

## 操作手册

界面顶部有 6 个页签：**查看模式 / 节点管理 / 道路管理 / 路径搜索 / 比例尺 / 项目**。

### 第 0 步：上传底图

左侧「地图底图」区域点 **上传地图图片**，选择一张本地地图图片
（PNG / JPEG / WEBP / GIF / BMP / AVIF，上限 60MB）。上传后显示原始尺寸并自动适配窗口。

> 更换底图会清空当前所有节点与道路（原点与尺寸可能不同），系统会先提示确认。

### 第 1 步：添加节点

1. **坐标输入**（节点管理页签）：填写 X / Y（原始像素坐标）与名称，点「添加节点」。
   超出范围或非数字会被阻止并给出具体提示。
2. **点击地图**：在节点管理页签下直接点击地图上的位置，按当前像素坐标添加。

节点有三种类型，颜色不同：**路口/交叉点**（红）、**出入口**（蓝）、**地标**（绿）。

- **新建节点默认是「地标」**，保证添加后在地图上立刻可见。
- **「路口/交叉点」类型的节点只在「节点管理」和「道路管理」页签显示**；
  查看模式、路径搜索、比例尺、项目等页签只显示出入口与地标，让画面更干净。
  节点数据、道路折线、路径搜索都不受影响——隐藏的只是标记。
- 需要把某个节点标为路口，请在节点管理页签的列表里用「节点类型」下拉框切换。

### 第 2 步：缩放与拖动

- **滚轮**：以鼠标位置为中心缩放
- **拖动空白处**：平移地图
- **适配窗口**：让整张底图完整可见
- **原始像素 1:1**：按 1 个图片像素 = 1 个屏幕像素显示

缩放与拖动只改变显示，**不改变任何坐标数据**。

### 第 3 步：创建道路

1. 切到「道路管理」页签
2. 选择**起点节点**与**终点节点**，有两种方式：
   - **在地图上点**（推荐）：点「点地图选起点」，然后在地图上单击任意节点，
     起点自动填入并切换到选终点；再单击另一个节点即可。起点与终点不能是同一个节点。
   - **用下拉框选**：直接从「起点节点 / 终点节点」下拉框挑选。
3. 点「绘制道路」，地图进入绘制模式
4. 依次点击地图添加**任意多个中间点**（可跳过，直接连直线）
5. 点「完成绘制」保存

道路是**双向**的，用线条表示（无方向箭头）。同一对节点之间只允许一条道路。

> 离开「道路管理」页签会自动退出端点选取状态，不会在其他页签误选端点。

### 第 4 步：修改与删除

- **拖动中间点**：在道路管理页签按住中间点手柄拖动即可改线形
- **重新绘制**：道路列表中点「重新绘制」
- **删除道路**：道路列表中点「删除」
- **删除节点**：节点列表中点「删除」；若该节点连接了道路，会提示将**一并删除**这些道路

删除后，已有的搜索结果与路线高亮会立即失效清空，不会残留过期结果。

### 第 5 步：校准比例尺

1. 切到「比例尺」页签
2. 点「开始选取」，在地图上点两个已知距离的点 A、B
3. 输入这两点之间的**真实距离**并选择单位（米 / 千米）
4. 点「应用校准」

校准后系统换算出「1 像素 ≈ X 米」，此后所有长度都显示为**米/千米**。

> 切换页签时校准点会自动隐藏，但已保存的比例尺不受影响。
> 底图存在透视变形时结果属于**估算**，不适用于测绘级精度。
> 未校准时长度只显示「像素」，绝不混用米。

### 第 6 步：路径搜索

1. 切到「路径搜索」页签，选择起点与终点
2. 点「搜索路径」，同时得到：
   - **全部简单路径**：所有不重复经过节点的路径，每条显示 `节点1 -> 节点2 -> 节点3` 与长度
   - **最短路径**：节点序列与估算距离，并标注本次搜索的起点/终点
3. 点任一结果，地图上高亮该路线的所有节点与道路折线；可随意切换
4. 两点不连通时显示 **「当前无路径」**，并清除旧高亮

为保证浏览器不卡死，路径数量有上限；结果被截断时界面会**明确标注「结果已截断」**，
不会把截断结果当成完整结果展示。

### 第 7 步：导出与导入项目

切到「项目」页签：

- **导出项目 JSON**：保存为 `.tianhe.json`，包含底图（base64 内嵌）、原始尺寸、
  节点、道路端点与折线中间点、比例尺参数、项目配置。
- **导入项目 JSON**：选择文件后先完整校验；当前已有数据时会提醒将被替换，可**取消**，
  取消后原数据一字不改。

**关于保存范围（重要）**：本系统**不使用**浏览器 localStorage / IndexedDB。
数据只存在于当前页面内存和你导出的文件里：

- 刷新页面或关闭标签页会丢失未导出的修改
- 换电脑、换浏览器必须靠导出文件迁移
- 好处是不会在你不知情时写入浏览器存储，也不会因存储配额写满而静默失败

## 坐标约定（重要）

所有节点坐标保存的都是**原始图片像素坐标**：

- 原点为图片左上角 `(0, 0)`
- X 向右为正，Y 向下为正
- 有效范围为 `X ∈ [0, 图片宽度]`、`Y ∈ [0, 图片高度]`，超出会被拒绝并提示

缩放与平移只作用于视图（相机）层，**不会修改**已保存的坐标，因此任意缩放 / 拖动 /
调整窗口大小后，节点与道路始终贴合原图位置（实测偏差 0.0000px）。

核心变换只有一条：`屏幕坐标 = 像素坐标 × 缩放 + 平移量`，图片与 SVG 覆盖层共用同一个
`transform`，业务数据中只存原始像素坐标。

## 核心技术说明

### 路径搜索

- **只使用已有道路**：搜索过程严格只读，不新增、修改或删除任何节点与道路。
- **双向**：每条道路在邻接表中同时生成正向与反向两条边。
- **边权 = 道路完整折线的像素总长度**：起点 → 中间点 1 → … → 终点逐段累加，
  **不是**两端点之间的直线距离。
- **简单路径**：DFS + 回溯枚举，路径中不重复经过同一节点。
- **最短路径**：Dijkstra 算法，边权同上。
- **数量保护**：最大结果数（默认 200）与内部展开次数上限（默认 200000）。
  达到上限时标记为**非完整**，界面显示「非完整结果（已达到上限）…并非全部路径」。
- **起点与终点相同**：稳定返回 1 条仅含该节点、长度为 0 的路径，并给出专门说明。
- **图数据改动**会使既有搜索结果失效，避免展示过期结果。

### 比例尺与距离估算

- **换算公式**：`米/像素 = 已知距离(米) / 两点像素距离`；`实际距离 = 折线像素长度 × 米/像素`。
- **像素长度**按每条道路的完整折线逐段欧氏距离累加。
- **显示规则**：小于 1000 米显示「米」（1 位小数）；大于等于 1000 米换算为「千米」（2 位小数）。
- **未校准**：只显示「像素」，并明确提示未校准，绝不把像素写成米。
- **已校准**：只显示实际长度（米/千米），不再显示像素数值。
- **最短路径权重**仍是折线像素长度；因「米 = 像素 × 正系数」是严格线性单调变换，
  最短路径的节点序列与按米加权完全一致。
- **精度限制**：假定图片横纵比例一致。若底图有明显透视变形，结果只是**近似估算**。

### 路线可视化

- **节点配色**：起点 `#059669`（翠绿）、终点 `#db2777`（品红）、路线中间节点
  `#7c3aed`（紫）、普通节点按类型着色（路口红 / 出入口蓝 / 地标绿），四者互不相同。
- **路线高亮**：由道路图层直接绘制，**复用该道路的真实折线坐标**（含全部中间点），
  不会在两端点之间画直线，因此缩放、拖动后与底层道路完全重合。
- **切换路线**：纯渲染行为，**不修改任何节点、道路或距离数据**。
- **道路选中**：点击一条道路即选中并高亮；**再次点击同一条取消选中**；点另一条则切换。
- **无路径**：显示「当前无路径」，同时清除旧路线高亮。

### 道路数据模型

每条道路是**无向边**，几何为有序点列：`A 节点 → 中间点 1 → … → B 节点`。

```ts
interface Road {
  id: string;              // 唯一 ID
  name?: string;           // 可选自定义名称，默认显示为「A ⇄ B」
  fromNodeId: string;      // 端点节点 ID
  toNodeId: string;        // 端点节点 ID
  points: PixelPoint[];    // 仅中间点，原图像素坐标，数量不限（0 个表示直连）
  createdAt: string;
}
```

设计要点：

- **只存中间点**，端点坐标渲染时由 `nodes` 实时解析（`buildRoadPolyline`），
  因此移动节点后折线端点自动跟随，不会出现坐标副本不一致。
- 中间点数量**不固定**，也**不会**被简化成直线。
- 同一对节点之间不允许重复建路，反向（B→A）同样视为重复。
- 删除节点时，与其关联的道路会被**级联删除**，确认框中明确列出数量，不留悬空引用。

### 项目文件格式

```jsonc
{
  "app": "tianhe-navigation",   // 应用标识
  "version": 1,                 // 格式版本
  "image": {
    "fileName": "my-map.png",
    "width": 1600, "height": 1200,
    "mimeType": "image/png",
    "dataUrl": "data:image/png;base64,..."   // 内嵌底图，可能为 null
  },
  "nodes": [
    { "id": "...", "name": "天河体育中心", "point": { "x": 400, "y": 300 },
      "type": "landmark", "createdAt": "..." }
  ],
  "roads": [
    { "id": "...", "fromNodeId": "...", "toNodeId": "...",
      "points": [ { "x": 700, "y": 180 } ] }   // 只存中间点
  ],
  "scale": {                     // 未校准时为 null
    "pointA": { "x": 0, "y": 0 }, "pointB": { "x": 1000, "y": 0 },
    "knownDistance": 2000, "unit": "m",
    "knownDistanceMeters": 2000, "pixelDistance": 1000,
    "metersPerPixel": 2, "calibratedAt": "..."
  },
  "config": { "exportedAt": "...", "maxResults": 200 }
}
```

**为什么内嵌 base64**：浏览器出于安全限制无法通过文件路径重新读取本地图片，
且路径在别人电脑上并不存在。只有内嵌进 JSON，导出文件才能在任意机器上完整恢复。

**导入校验**覆盖：JSON 语法 → `app`/`version` → 图片字段与尺寸 → 节点 id 唯一性 /
坐标 / 类型 → 道路端点引用有效性 / 自环 / 重复端点对 / 折线点坐标 → 比例尺各项。
任一项失败都会给出**中文原因 + 出错位置**（如 `roads[0].toNodeId`），
并提示「当前项目数据未被修改」。

**未内嵌底图的文件**：节点、道路、比例尺照常导入并保留，
地图区明确提示「已导入数据，但缺少底图」，选择同一张底图即可恢复显示。

## 示例数据

`examples/demo-tianhe.tianhe.json` 是一份可直接导入的演示项目：

- 底图：仓库自带的 `test-map.png`（1600×1200，本地生成，**未联网获取**）

导入后可选「天河体育中心 → 体育东路」搜索，应得到 **5 条路径**，最短 **1.76 千米**。

> 示例数据只为演示功能，**不能代替你自己的地图**。
> 正式使用请上传你自己的天河体育中心周边地图并重新标定比例尺。

## 部署

`pnpm build` 生成的 `dist/` 是**纯静态文件**，可直接上传到任意静态托管
（Nginx、GitHub Pages、对象存储、CDN 等），无需数据库或后端服务。

- 若部署在子路径（如 `https://example.com/nav/`），在 `vite.config.ts` 中设置
  `base: '/nav/'` 后重新构建。
- 页面无路由依赖，不需要服务器做 SPA 回退配置。

## 已知问题与限制

1. **没有自动保存**：不使用 localStorage / IndexedDB，刷新或关页会丢失未导出的修改
   （有意设计，见上文）。
2. **比例尺为估算值**：底图存在透视变形时，不适用于测绘级精度。
3. **仅实测 Chromium**：Firefox / Safari 未实测。
4. **大图未压测**：60MB 上限的底图内嵌后 JSON 可达约 80MB，未测导出/导入耗时与内存峰值。
5. **复杂路网会截断结果**：简单路径数量指数增长，系统会截断并明确标注「已截断」。
6. **同一对节点仅允许一条道路**：需要并行线路时请插入中间节点。
7. **节点名称允许重复**：名称是标签，唯一性由 id 保证。
8. **无撤销 / 重做**：删除不可撤销，但删除前均有确认提示。
