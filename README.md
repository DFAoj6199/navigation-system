# 天河体育中心周边地图可视化导航系统

基于浏览器运行的地图可视化导航系统。当前为**阶段 5：路线可视化与搜索结果展示**。

> 地图底图**必须由用户自行上传**。系统不联网获取地图，不内置任何示例地图，也不会自动替换底图。

## 技术栈

- React 19 + TypeScript 5.9
- Vite 8（开发与构建）
- Zustand 5（状态管理）
- Vitest（单元测试）+ Playwright（真实浏览器 E2E 验收）
- 地图渲染：原生 `<img>` + SVG 覆盖层，坐标与原始图片像素一一对应

## 安装与启动

需要 Node.js ≥ 20（当前环境实测 v24.16.0）与 pnpm。

```bash
pnpm install
pnpm dev
```

启动后浏览器打开终端输出的地址，默认 <http://127.0.0.1:5173/>。

生产构建与本地预览：

```bash
pnpm build
pnpm preview
```

## 使用方法

1. 在左侧“地图底图”区域点击 **选择本地地图图片**，选择你自己的天河体育中心周边地图（支持 PNG / JPG / WEBP / GIF / BMP / AVIF，≤ 60MB）。
2. 上传后可在地图区域拖动平移、滚轮缩放，或使用工具栏的“适配窗口 / 原始像素 1:1”。
3. 添加节点有两种方式：
   - 顶部切换到 **添加节点** 模式，在地图上单击；
   - 左侧“手动添加节点”中输入原始像素坐标 X、Y（可选填名称）。
4. 在“节点列表”中可以选中、改名、修改坐标、修改类型和删除节点。

## 坐标约定（重要）

所有节点坐标保存的都是**原始图片像素坐标**：

- 原点为图片左上角 `(0, 0)`；
- X 向右为正，Y 向下为正；
- 有效范围为 `X ∈ [0, 图片宽度]`、`Y ∈ [0, 图片高度]`，超出会被拒绝并提示。

缩放与平移只作用于视图（相机）层，**不会修改**已保存的节点坐标，因此任意缩放/拖动/调整窗口大小后，节点始终贴合原图位置。

### 路径搜索说明（阶段 3）

- **只使用已有道路**：搜索过程严格只读，不新增、修改或删除任何节点与道路。
- **双向**：每条道路在邻接表中同时生成正向与反向两条边。
- **边权 = 道路完整折线的像素总长度**：起点节点 → 中间点 1 → … → 终点节点 逐段累加，
  **不是**两个端点之间的直线距离。同一对节点若折线绕行，长度会明显大于直线距离。
- **单位恒为“像素”**：比例尺尚未校准，界面统一标注为像素，不代表实际米数。
- **简单路径**：DFS + 回溯枚举，路径中不重复经过同一节点。
- **最短路径**：Dijkstra 算法，边权同上。
- **数量保护**：`最大结果数`（默认 200）与内部展开次数上限（默认 200000）。
  达到上限时结果标记为**非完整**，界面明确显示“非完整结果（已达到上限）…并非全部路径”，
  绝不把部分结果说成全部路径。
- **起点与终点相同**：稳定返回 1 条仅含该节点、长度为 0 像素的路径，并给出专门说明。
- **无路径**：显示“当前无路径”。
- 图数据（节点/道路）任何改动都会使既有搜索结果失效，避免展示过期结果。

### 比例尺与距离估算说明（阶段 4）

- **校准方式**：在“比例尺”页签进入地图点选模式，依次点选两个位置（自动换算为原始图片像素坐标），
  再输入这两点的已知实际距离与单位（米 / 千米），点击“应用校准”。
- **换算公式**：`米/像素 = 已知距离(米) / 两点像素距离`；之后
  `实际距离(米) = 折线像素总长度 × 米/像素`。
- **像素总长度**：按每条道路的完整折线，把相邻点之间的欧氏距离逐段累加，
  **不是**两个端点之间的直线距离。
- **单位换算与小数位**：小于 1000 米显示为“米”（1 位小数）；大于等于 1000 米自动换算为“千米”（2 位小数）。
- **未校准时**：只显示“像素”，并明确提示未校准，**绝不把像素长度写成米**。
- **已校准时**：路径结果与道路列表**只显示实际长度**（米/千米），不再显示像素数值。
- **校准点显示**：校准点与连线只在“比例尺”页签显示；切换到其他页签会暂时隐藏，
  回到比例尺页签自动恢复，且不影响已保存的比例尺。

### 路线可视化说明（阶段 5）

- **节点配色**：起点 `#059669`（翠绿）、终点 `#db2777`（品红）、所选路线上的中间节点
  `#7c3aed`（紫）、普通节点仍按类型着色（路口红 / 出入口蓝 / 地标绿），四者互不相同。
- **路线高亮**：高亮由道路图层直接绘制，**复用该道路的真实折线坐标**（含全部中间点），
  不会在两个端点之间画直线，因此缩放、拖动后与底层道路完全重合（实测偏差 0.0000px）。
- **切换路线**：点击结果列表任意一条即可切换高亮；切换是纯渲染行为，
  **不修改任何节点、道路或距离数据**。
- **结果标注**：结果区顶部显示“起点：X → 终点：Y”，取本次搜索的快照，
  不受搜索后改动下拉框的影响。
- **无路径**：显示“当前无路径”，并同时清除旧路线高亮，避免误导。
- **查看模式**：不显示节点管理与道路管理列表，进入对应页签才显示。
- **非法输入**：两点重合、距离为 0 或负数、非数字、单位非法、超出地图范围，都会被拒绝并给出具体原因，
  且不会破坏已有的比例尺。
- **最短路径权重**：边权仍是折线像素长度，因“米 = 像素 × 正系数”是严格线性的单调变换，
  最短路径的节点序列与按米加权完全一致，只是显示的距离按系数缩放。
- **与视图无关**：校准点与长度全部基于原始图片像素坐标，缩放、拖动地图不改变已保存的系数与实际长度。
- **精度限制**：本算法假定图片各方向比例一致（等比例）。若底图存在**透视变形**或横纵比例不均匀，
  结果只是**近似估算**，不具备测绘级精度。

### 道路数据模型

每条道路是**无向边**，几何为有序点列：`A 节点 → 中间点 1 → 中间点 2 → … → B 节点`。

```ts
interface Road {
  id: string;              // 唯一 ID
  name?: string;           // 可选自定义名称，默认显示为“A ⇄ B”
  fromNodeId: string;      // 端点节点 ID
  toNodeId: string;        // 端点节点 ID
  points: PixelPoint[];    // 仅中间点，原图像素坐标，数量不限（0 个表示两点直连）
  createdAt: string;
}
```

设计要点：

- **只存中间点**，端点坐标在渲染时由 `nodes` 实时解析（`buildRoadPolyline`）。因此移动节点后折线端点自动跟随，不会出现坐标副本不一致。
- 中间点数量**不固定**，也**不会**被简化成两端点之间的直线。
- 同一对节点之间不允许重复建路，反向（B→A）同样视为重复。
- 删除节点时，与其关联的道路会被**级联删除**，并在确认框中明确列出数量，绝不留下悬空引用。
- 所有道路均为**双向**；存储中无方向字段，后续路径搜索需同时建立正向与反向邻接关系。
